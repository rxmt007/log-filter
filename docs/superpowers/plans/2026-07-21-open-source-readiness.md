# 开源发布准备实施计划

**目标:** 在创建新的公开仓库前，完成许可选择、文档整理、隐私与密钥审计，并使项目元数据与社区协作说明保持一致。

**范围:** 只调整文档、项目元数据、许可文件和审计中确认需要替换的示例数据；不改变日志引擎、IPC 或界面功能。`docs/videos/` 当前未纳入 Git，本计划不提交该目录。

## 约束

- 保持 `main` 与 `dev` 对齐，只向新仓库推送这两个正式分支。
- 不恢复旧仓库的 PR、Actions 运行记录或其他平台元数据。
- 新提交继续使用 GMT+8 的已过去周末时间，并严格晚于父提交。
- 写入仓库的内容不得包含真实本地路径、个人联系信息、设备标识、密钥或真实内网地址。
- 修改前后运行项目完整验证命令；发布前另做一次历史级敏感信息扫描和独立审查。

## Task 1：许可与来源关系审查

- [x] 核对原项目公开仓库中的许可声明与源码版权提示。
- [x] 比较 GPLv3 与 AGPLv3 对桌面应用的实际影响，形成书面结论。
- [x] 盘点 Rust、前端依赖的许可证，确认与选定许可证没有明显冲突。
- [x] 添加标准许可文本，并同步 Cargo、npm 与 README 中的 SPDX 标识。
- [x] 在 README 中说明独立重写关系、致谢原项目，并避免暗示复制源码或官方关联。

## Task 2：公开文档整理

- [x] 重写 README 的项目简介、平台状态、构建、文档、贡献、致谢与许可章节。
- [x] README 只链接 Markdown 文档；HTML 副本仅说明需下载后在本地打开。
- [x] 将用户手册中的“5 分钟上手”及口语化操作标题改为中性表述。
- [x] 明确 macOS 构建未签名、未公证，且仅 macOS Apple Silicon 完成手动测试。
- [x] 将架构文档从内部交接语气调整为面向社区贡献者的工程说明。
- [x] 同步更新保留的 HTML 用户手册和架构说明中的对应内容。

## Task 3：社区协作与项目元数据

- [x] 添加 `CONTRIBUTING.md`，说明开发环境、验证命令、提交与 PR 约定。
- [x] 补齐 Cargo 与 package.json 的 description、license、repository、bugs 等字段。
- [x] 删除内部设计平台的项目标识，并将示例内网地址替换为文档专用地址。
- [x] 更新 AGENTS.md 中的公开仓库状态和社区协作约定。

## Task 4：验证、审查与发布

- [x] 扫描当前文件、未跟踪文件及正式 Git 历史中的路径、个人信息、设备信息和密钥模式。
- [x] 校验 Markdown 链接、HTML 链接规则、许可证标识和文档一致性。
- [x] 运行 Rust、Tauri、前端完整验证命令。
- [x] 由独立审查者检查最终 diff 与审计结论。
- [ ] 创建一个符合周末时间约束的提交，将 `dev` 快进到同一提交。
- [ ] 创建新的同名仓库，只推送 `main`、`dev`，并核对远端历史和默认分支。
