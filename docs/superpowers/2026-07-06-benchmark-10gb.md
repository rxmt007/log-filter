# 10GB 基准报告(2026-07-06)

工具:`crates/logcore/examples/bench.rs`(可复跑,作回归基准)。
命令:`/usr/bin/time -l ./target/release/examples/bench 10 <file>`。
环境:macOS(开发机,Apple Silicon),release 构建,单线程引擎。
语料:合成 threadtime,10.00 GiB / 71,158,201 行(含 1KB 长行与 raw 分隔行)。

## 结果

| 指标 | 数值 | 判定 |
|---|---|---|
| 索引耗时 / 吞吐 | 20.6s / **498 MB/s**(3.46M 行/s) | ✅ 10GB 打开约 20s 可完整浏览 |
| 索引单步锁停顿(8MB 步进) | avg 16.1ms / **max 36.9ms** | ✅ 索引期滚动最坏等待 ~37ms |
| 过滤:级别掩码 | 5.8 M行/s(全量 ≈ 12.2s) | ✅ 后台任务执行,UI 不阻塞 |
| 过滤:tag 多值明文 | 5.4 M行/s | ✅ |
| 过滤:关键词明文(高命中 39.6M) | 5.3 M行/s | ✅ |
| 过滤:正则多值 | 3.7 M行/s(≈ 19.2s) | ✅ |
| 窗口读 get_rows(200 行) | All p99 **1.56ms** / Filtered p99 1.24ms | ✅ 滚动流畅 |
| 搜索(明文不敏感) | 4.4 M行/s(≈ 16.1s) | ✅ |
| 导出 Filtered(3.56M 行 / 506MiB) | **17 MB/s**(29.8s) | ⚠️ 见"发现" |
| 导出 All(71.2M 行 / 10GiB) | **32 MB/s**(≈ 5.6min) | ⚠️ 见"发现" |
| 私有内存峰值(peak memory footprint) | **≈1.37 GiB** | ✅ 含全部命中数组 |
| max RSS | 11.1 GiB | ℹ️ 系 mmap 常驻干净页,可被系统随时回收,非真实占用 |

## 结论

"10GB 不崩不卡"目标在索引、过滤、搜索、滚动路径上已达成:全程无崩溃,索引 20s,交互操作(滚动/窗口读)毫秒级,重扫描(过滤/搜索)在后台 12-19s 完成且不阻塞 UI。

## 发现:导出吞吐偏低(已定位)

导出路径对每一行独立调用 `line_span`——从最近检查点(步长 1024 行)向前逐行 memchr 扫描,平均每行多扫 ~512 行,复杂度 O(行数 × 步长)。过滤/搜索用的批量 `line_spans` 是顺序前向扫描 O(行数),快一个数量级以上。导出的行号数组本身升序,可改为同样的前向批量解析。预期导出吞吐可达数百 MB/s(接近顺序 IO 上限)。

## 备注

- 生成器吞吐 294 MB/s(仅供参考,不属于引擎指标)。
- 单步锁停顿如需进一步压低,可把 `INDEX_BUDGET` 从 8MB 降到 4MB(停顿减半,索引总耗时几乎不变),暂无必要。
- 过滤/搜索的进一步提速方向是 rayon 分块并行(引擎单测已按 4096 行分块,天然可并行),等有真实需求再做。
