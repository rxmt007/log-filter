Product direction · decision brief

从数千万行文本，收敛成可信、可复现、可安全交付的调查路径。

下一阶段不扩张为通用日志平台，也不复制 Android Studio。LogFilter 应把已有的 10GiB 本地大日志、确定性 Problems 与实时抓取底座，串成一条更快形成调查结论的工作流。

本地优先原始证据只读事实边界可见get_rows ≤ 512单 Session 不变量

North star

确认采集可信 → 恢复调查方法 → 定位复现窗口 → 理解局部证据 → 保存调查状态 → 安全分享。
证据不改写派生视图始终能回到原始来源、范围和 coverage。
不伪造确定性Unknown、近似、时间回拨和有损采集必须可见。
性能不退化摘要、sidecar 与新来源都不能把正文搬进前端。
一步一验证高风险方向先过事实、用户理解和性能验证门。

Priority, not calendar

三段式路线图

优先级表示“下一次学习的顺序”，不是日期承诺。每一段只有通过验证门，才进入功能设计与工程计划。

P0现在：先让调查可信3 directions
  • 抓取健康度与空结果解释先区分断流、暂停、源无数据和零命中。
  • 命名调查配方把常用过滤与视图变成可恢复的方法。
  • 时间定位与时间范围从复现时间直接抵达可解释的上下文。
P1下一步：完成本地闭环7 directions
  • 安全分享 + 调查会话保存调查状态，并输出可审查的脱敏副本。
  • 结构化检查 + 密度摘要理解局部证据，快速找到刷屏与突增。
  • Problems 缓存严格校验后复用分析，不复制正文。
  • 两项验证门进程身份与有损采集先验证事实和心智模型。
P2探索：扩展证据边界6 directions
  • bugreport + 证据包共享 provenance 基础，来源永不被抹平。
  • 源码定位 + Perfetto handoff到达日志证据边界时，升级到本地工具链。
  • 摘要差异 + 两来源并排只比较有界摘要，MultiSource 模型先行。

P0-1可信采集抓取健康度与明确恢复

用分层诊断解释“为什么没有日志”，并只给当前状态对应的恢复动作。

进入原型

唯一方案：工具栏健康胶囊 + 表格上方 context banner + 状态栏源状态；不另做监控首页。

用户问题
用户看到零日志时，无法判断是主动暂停、ADB 子进程退出、设备连接正常但无字节、源本身无数据，还是显示过滤后零命中，容易误查业务代码。
核心价值
在调查业务问题前先证明证据链是否健康，降低“工具故障被当成应用故障”的误判成本。
主要交互流程
健康胶囊显示状态 → 展开来源、传输、最后字节、过滤前后计数与 coverage → 执行“继续”“重新连接”或“清除显示过滤” → 续抓后说明边界重复。
功能边界
首版不静默无限自动重启；不把安静期表述成“应用无日志”；不隐藏 `-T` 续抓同毫秒重复和 coverage 不确定性。
依赖
现有 stream 状态、错误事件、generation、过滤计数、最后收字节时间、设备状态和 `-T` 续抓。
风险
自然安静与断流难区分；状态竞态、抖动、恢复竞争和边界重复可能制造新的误导。
优先级
P0。误判代价高、现有架构复用度最高，也是所有实时调查的信任入口。
验证方式
注入暂停、断开、进程退出、静默源和零命中；目标用户 15 秒内正确识别并恢复；续抓无静默丢数，coverage 与重复边界可解释。
P0-2可复现方法命名调查配方

把过滤、视图、列与采集引用保存为结构化配方，默认替换当前状态。

进入原型

唯一方案：在过滤栏放一个“配方”选择器；保存与覆盖复用紧凑对话框，不引入 DSL 或常驻侧栏。

用户问题
常用调查依赖多个过滤开关、RowsView、列显隐/宽度、高亮、软换行和缓冲区，用户很难准确重建。
核心价值
把个人操作经验变成可解释、可复现的一键调查方法，减少记忆和误操作。
主要交互流程
配置当前视图 → 保存为配方 → 填写名称与说明并核对纳入字段 → 从配方选择器恢复 → 默认“替换”，另有明确“合并”及变更预览。
功能边界
不保存设备 serial、源文件、凭据或调查笔记；首版无自由文本 DSL、云同步或多人共享；只引用 ADB 命令/缓冲区。
依赖
FilterSpec、RowsView、列宽/显隐、高亮、软换行、命令预设、TOML schema 与迁移。
风险
合并语义不清、旧版本字段失效、用户误以为保存了完整会话或设备身份。
优先级
P0。高频、不可逆风险低，直接补齐结构化过滤“可恢复”的心智模型。
验证方式
目标用户 30 秒内恢复常用调查视图；恢复后 FilterSpec 等状态逐字段一致；用户能预判替换/合并结果；迁移 fixture 通过。
P0-3复现定位时间跳转与时间范围

先定位 segment 内最近可比较行，再把调查限定在显式时间范围。

进入原型

唯一方案：工具栏 28px“时间”控件 + segment-aware 对话框 + 小地图范围带 + 状态栏实际覆盖。

用户问题
用户通常知道复现时间，却只能靠关键词或行号在数千万行中反复寻找相关上下文。
核心价值
从复现时刻直接抵达最近原文，并把后续过滤、Problems 与导出限定在可解释窗口。
主要交互流程
选择 segment → 输入 `MM-DD HH:MM:SS.mmm` 或起止范围 → 预览最近行与实际覆盖 → 跳转/应用 → 状态栏持续显示范围并可清除。
功能边界
先交付本 segment 跳转，再交付范围过滤；首版不做全页图表；不伪造跨年、回拨、多段拼接或无时间戳续行的绝对时间轴。
依赖
时间解析、segment、轻量稀疏时间检查点、FilterSpec 时间范围、行号映射、小地图与状态栏。
风险
跨年、设备时钟回拨、原始续行、空区间与范围叠加过滤可能造成错误定位。
优先级
P0。最贴近 Android QA 的真实复现任务，且不改变窗口化读取架构。
验证方式
与关键词路径比较定位耗时；用跨年、回拨、拼接和续行 oracle 验证；任何时间不确定性必须可见。
P1-1安全交付安全分享导出

在现有导出中增加“安全副本”模式，本地扫描、遮罩预览并生成规则报告。

进入原型

唯一方案：复用 ExportDialog 的独立“安全副本”模式；普通导出语义保持不变。

用户问题
日志在本地打开并不代表分享安全；普通导出可能把凭据、账号、设备标识或联系方式直接发到 Issue、邮件或群聊。
核心价值
本地生成可审查、可追溯、不改源文件的脱敏副本，降低交付环节的隐私风险。
主要交互流程
选择“安全副本” → 选择范围 → 本地扫描 → 查看类别计数与少量遮罩样本 → 逐类启停 → 生成新文件和规则报告。
功能边界
源文件只读；只含高置信内置规则；占位符稳定且默认不可逆；报告不写原文；不联网；明确“未检出不等于绝对安全”。
依赖
流式导出、跨块匹配、规则版本、稳定占位符、进度/取消和正负例语料。
风险
漏报、误报、跨块泄漏、预览本身暴露敏感值、10GiB 扫描成本和规则治理。
优先级
P1。直接支撑“可分享且不泄密”的定位，但必须先建立规则质量和性能基线。
验证方式
合成正负例与跨块边界；记录精确率/召回率、10GiB 吞吐和私有内存；断网验证；源哈希不变且报告零原文。
P1-2重复打开性能Problems sidecar 缓存

严格校验文件身份、规则与 schema 后恢复紧凑分析索引，任一失配即完整重扫。

状态反馈，不独立原型

唯一方案：Problems dock 头部显示“身份已验证 / 缓存命中 / 从稳定前沿继续”；不建设缓存管理页面。

用户问题
重复打开 10GB 文件仍需等待完整 Problems 扫描，打断回看和隔日继续调查。
核心价值
在不牺牲事实正确性的前提下显著缩短重开时间，并支持增长文件从稳定前沿继续。
主要交互流程
打开文件 → 校验身份、编码/profile、规则/指纹和 schema → 命中则恢复 coverage → 增长文件继续分析 → 失配或损坏自动重扫并说明原因。
功能边界
只存紧凑 group/occurrence/observation 索引，不复制正文；不把旧缓存或损坏缓存降级成“可用近似”。
依赖
规范化文件身份、大小/修改信息、分段哈希、stable frontier、编码/profile、规则/指纹/schema 版本与原子写入。
风险
陈旧事实、哈希碰撞、部分写入、损坏 sidecar，以及校验耗时抵消收益。
优先级
P1。收益明确且架构契合高，但错误命中会制造错误事实，正确性优先于速度。
验证方式
冷开、命中、尾部增长、编码/规则变化、碰撞和损坏回退矩阵；缓存结果与全量重扫逐字段一致，并记录实际节省。
P1-V3事实验证门进程 / package 身份过滤

只按生命周期事实建立 `(segment, pid, lifetime)` 映射，Unknown 保持 Unknown。

验证项

唯一方案：离线身份映射先行；通过 oracle 后才在现有过滤栏增加 process/package 条件，绝不先造纯 UI 输入框。

用户问题
PID 会因重启变化并被复用，历史 `threadtime` 行通常没有 package；手工 PID 过滤无法稳定跟踪应用。
核心价值
跨进程重启跟踪真实应用生命周期，同时避免把复用 PID 的其他进程混入结果。
主要交互流程
从确定性生命周期事实建立映射 → 用户选择 process/package → 只纳入确认归属区间 → 显示未映射 coverage 与来源证据。
功能边界
Unknown 保持 Unknown；不按当前 PID、Tag 或启发式猜测历史身份；先离线验证，不与采集前过滤混成一个控件。
依赖
AOSP lifecycle 事件、segment、版本化身份映射、lifetime provenance 与 logcore 过滤扩展。
风险
OEM 格式差异、生命周期事件缺失、多进程应用、PID 重用和错误归属。
优先级
P1 验证门。价值高但事实基础尚不稳定，不能提前承诺产品化。
验证方式
用含 PID 重用、重启和多进程的 oracle 分别统计漏入/误入，以零错误归属为首要指标，再用已脱敏真实样本复核。
P1-V4有损能力验证门可选采集前过滤

在采集设置中独立、默认关闭，仅允许官方 buffer/tag/level 并持续显示有损 coverage。

验证项

唯一方案：来源/命令区的“采集范围（有损）”，与可逆显示过滤分层；开启后整个会话持续琥珀提示。

用户问题
极端日志洪水会在显示过滤前堵塞 ADB 传输、增加落盘压力，甚至把目标日志挤出设备环形缓冲区。
核心价值
在用户明确接受丢失风险时减少上游传输与落盘压力，让噪声设备仍可采集目标范围。
主要交互流程
高级采集设置主动开启 → 确认不可恢复警告 → 选择官方 buffer/tag/level → 新会话开始 → 全程显示有损 coverage；改范围需重启会话。
功能边界
默认完整采集；绝不把显示 FilterSpec 静默下推；首版不支持未验证的 package/正则采集；未采集数据不可恢复。
依赖
ADB 命令计划、设备能力检测、coverage 元数据、健康状态、会话 provenance。
风险
永久丢失关键上下文、设备版本语义差异、命令转义、警告疲劳和用户误把它当显示过滤。
优先级
P1 验证门。只在噪声场景高价值，先验证用户是否真正理解损失边界。
验证方式
比较受控噪声下的延迟、吞吐、落盘量和目标保留率；命令生成矩阵；用户能准确解释采集范围与显示过滤的区别。
P1-5局部理解可见范围结构化检查器

在 Problems 式底部 dock 解析选中行，Raw/Structured 可切换并生成现有过滤条件。

进入原型

唯一方案：选中行后在底部详情 pane 展开 JSON/logfmt/XML；不新增永久右栏或独立查看器。

用户问题
JSON、logfmt 或 XML 嵌在单行消息中难读，复制字段再构造包含/排除条件费时且易错。
核心价值
在不破坏大文件窗口化架构的前提下理解局部结构，并一键回到全局过滤调查。
主要交互流程
选择日志行 → dock 自动识别格式 → Raw/Structured 切换 → 展开/复制字段 → 生成包含或屏蔽条件 → 后端按原语义重扫。
功能边界
只解析选中行或固定小窗口；限制字节、深度和节点数；失败保留 Raw；不加载实体、URL 或外部资源。
依赖
`get_rows ≤512`、有界安全解析器、字段到 FilterSpec 的映射与剪贴板。
风险
格式误判、深度/实体炸弹、巨大字段、DOM 注入和敏感值在 UI 中暴露。
优先级
P1。用户价值直观，架构契合高，且范围可严格有界。
验证方式
正常、畸形、超深和超大 fixture 与 fuzz；固定内存上限、零网络请求；生成条件与手工 FilterSpec 结果一致。
P1-6大日志导航多分辨率密度与噪声摘要

用 segment 时间桶和 Top tag/pattern 找突增，再从样本行跳回原始证据。

进入原型

唯一方案：放在底部 dock 的紧凑密度条 + Top 列表；点击桶限定时间，绝不做独立 dashboard。

用户问题
面对 10GB 日志，用户无法快速回答“何时爆量、主要在刷什么”，只能靠盲目滚动或猜关键词。
核心价值
把超大日志收敛成可解释、可跳回原文的导航线索，缩短定位噪声和突增的时间。
主要交互流程
打开摘要 dock → 查看 segment 时间桶与 Top tag/pattern → 查看次数、首末位置、exact/approx 和样本 → 点击桶/模式跳转或形成可撤销过滤。
功能边界
只是导航和近似摘要，不是 Problems、根因或因果图；时间不可靠时改用行号尺度；始终保留样本与误差标记。
依赖
时间 segment、分桶索引、top-K/sketch、模式指纹版本和样本行号映射。
风险
模板碰撞、稀有事件被淹没、近似误导、时钟断点和增量更新成本。
优先级
P1。与大文件优势高度契合，但依赖 P0 时间基础和明确解释边界。
验证方式
已知分布语料的误差界；点击回原文准确性；10GiB 性能与固定内存；比较用户定位刷屏源的任务耗时。
P1-7暂停与恢复调查会话 sidecar

保存文件身份、配方、稳定引用、返回点和少量备注，事实与用户笔记始终分栏。

进入原型

唯一方案：Problems 式底部 dock 的“调查会话”页签；本地 sidecar 自动保存，源失配时只读展示并明确失效。

用户问题
选中的 Problems、注释书签、配方和返回位置分散；隔日重开后调查上下文丢失。
核心价值
让调查可暂停、恢复和复盘，同时不复制整份日志或混淆事实与笔记。
主要交互流程
固定 Problem/书签 → 添加显式用户备注 → 关联配方与返回点 → 本地自动保存 → 重开时校验文件身份 → 匹配则恢复，失效引用明确标记。
功能边界
首版单来源、本地 sidecar；只存身份、行号、稳定引用和少量备注，不复制原文；不自动重绑失效行号。
依赖
文件身份、书签、Problems 稳定引用、配方 schema、返回点和迁移机制。
风险
源变更造成悬空引用、用户备注被误读成事实、sidecar 本身含敏感内容和 schema 迁移。
优先级
P1。是后续调查证据包和跨人交接的必要基础。
验证方式
隔日恢复、完整 round-trip、尾部变化、错误文件、损坏和迁移；用户能稳定区分 deterministic fact 与 user note。
P2-1来源扩展bugreport 只读导入器

安全盘点 ZIP 成员并逐个作为独立来源打开，派生事实保留 member 与原始字节范围。

架构验证门

唯一方案：从“来源”下拉进入只读导入，先显示 manifest，再一次激活一个受支持成员；不画伪连续时间线。

用户问题
完整 Android 故障证据散落在 ZIP 内的 logcat、ANR traces、tombstone、dumpsys 等成员中。
核心价值
在同一工作台阅读相关证据，同时保留每项来源、成员名和原始字节范围。
主要交互流程
打开 bugreport → 安全扫描 manifest → 展示成员、类型、大小和隐私提示 → 选择受支持成员 → 作为独立来源打开 → 派生事实可回溯。
功能边界
不把成员拼成伪连续 logcat；白名单只读解析；不一次性解压进内存；首版一次激活一个来源，不做符号化。
依赖
provenance、来源模型、安全 ZIP 读取、临时文件/磁盘预算、格式适配器；多来源形态需 MultiSource 基础。
风险
Zip Slip、zip bomb、磁盘耗尽、重复证据、来源错配和更高隐私等级。
优先级
P2。价值高但会改变来源/Session 模型，应在 provenance 与只读 probe 成熟后推进。
验证方式
恶意 ZIP、AOSP golden corpus、来源/字节范围往返、资源上限、失败清理；在来源模型确认前不接正式 UI。
P2-2可复现交接调查证据包

把 raw evidence、deterministic facts 与 user notes 分层装入版本化本地包。

依赖 P1

唯一方案：从调查会话进入安全导出，生成带 manifest、hash 和 schema 的独立格式；不污染 `.log`。

用户问题
仅分享过滤文本会丢失配方、范围、事实来源、书签和调查备注，接收者无法复现路径。
核心价值
交付可校验、可复现、事实边界清楚的本地调查成果。
主要交互流程
从调查会话选择 raw ranges、Problems、书签、配方和备注 → 安全检查 → 预览 manifest → 生成离线包 → 接收方只读打开并校验哈希。
功能边界
raw、deterministic facts、user notes 三层分离；默认仅选定范围；不写根因结论、不上传云端；格式独立于 `.log`。
依赖
调查会话、安全分享、provenance、文件哈希、版本化容器和迁移策略。
风险
仍含敏感原文、篡改、包体膨胀、版本不兼容和用户备注被误读成事实。
优先级
P2。应建立在 P1 安全分享与调查会话之上，不宜独立抢跑。
验证方式
导出—导入确定性 round-trip、篡改检测、版本兼容、完全离线打开；由另一位用户复现同一调查路径。
P2-3本地工具链Java 堆栈源码定位

只在已配置源码根内解析 frame，预览相对路径后显式交给白名单编辑器。

安全验证门

唯一方案：Problems detail 中的 frame 动作；未解析时提供“复制搜索”，不执行日志路径。

用户问题
Java/Kotlin 异常帧需要人工复制类名和行号，再到工程中搜索。
核心价值
从已确认的 Problems frame 一步定位本地代码，减少机械查找。
主要交互流程
选择 frame → 在配置源码根中解析 → 预览相对路径、行号和候选歧义 → 显式用允许的编辑器打开；失败则复制搜索。
功能边界
不执行日志中的绝对路径或 URL；不联网下载源码；R8 mapping/native symbols 需后续显式本地导入。
依赖
frame 解析、源码根配置、路径规范化、根目录约束和编辑器协议白名单。
风险
路径遍历、命令注入、重名文件、错误 mapping 与源码版本不一致。
优先级
P2。能节省时间，但受外部工程环境影响且安全要求高，低于通用调查闭环。
验证方式
monorepo、多源码根、歧义、恶意路径、缺失与混淆 fixture；根目录逃逸必须为零；比较手工搜索耗时。
P2-4复现比较两次采集的摘要差异

只比较 Problems 指纹、模式/Tag 速率和重启密度，差异项回到双方样本。

依赖摘要

唯一方案：恰好两个本地会话的紧凑摘要比较；不可比时停止排名并解释原因，不做 10GB 文本 diff。

用户问题
修复前后或两次复现的 10GB 日志无法通过全文 diff 得到有意义的调查结果。
核心价值
突出值得调查的结构化变化，并保留双方样本与原文入口。
主要交互流程
选择 baseline/current → 核对时长、segment、coverage 和采集条件 → 归一化比较 → 展开变化 → 查看双方样本与原文。
功能边界
不是全文 diff，不合并行号空间，不输出自动回归/根因结论；只比较紧凑摘要；不可比就明确拒绝。
依赖
Problems 指纹、密度/模式摘要、provenance、采集元数据、时间覆盖和双来源协调。
风险
复现步骤、时长、时钟与采集配置差异制造假变化，近似统计放大误差。
优先级
P2。依赖多个前置摘要和来源能力，适合作为受控验证而非当前主线。
验证方式
成对控制语料中注入已知变化；时长/coverage 守门；不可比数据必须拒绝排名；用户能正确解释相对变化。
P2-5证据升级Perfetto 证据升级入口

从选定 Problem/时间范围生成本地 handoff，明确日志能证明和不能证明的内容。

边界验证

唯一方案：Problems/时间范围中的“升级证据”动作，生成 capture 指引与调查锚点；LogFilter 不复制 Perfetto 分析器。

用户问题
日志只能提示卡顿或 ANR 附近事件，无法证明 CPU 调度、Binder flow、锁竞争或真实 duration。
核心价值
明确日志证据已到边界，并为下一次复现准备更强的本地证据工作流。
主要交互流程
从 Problem/时间范围选择“升级证据” → 展示已知与未知 → 生成本地 Perfetto capture 配置、范围片段和 segment 锚点 → 交给外部工具。
功能边界
不内建性能分析器；不从纯日志补造 CPU、Binder 因果或 duration；`android.log` 不可用时不声称自动对齐。
依赖
时间 segment、范围导出、provenance、证据包基础与设备能力说明。
风险
时钟对齐错误、userdebug 限制、用户把时间邻近当因果，以及 handoff 片段泄密。
优先级
P2。属于证据升级，不应稀释 LogFilter 的本地日志主产品。
验证方式
受控 trace/log 对齐与已知偏移样本；不同设备能力文案正确；专家回放；用户能说明为什么需要额外 trace。
P2-X6P2/P3 边界探索多文件并排与时间对齐

首版固定两个来源、用户提供锚点、共享游标但保持独立行号与查询。

最后推进

唯一方案：引擎级 Two-source MultiSource Session + 双泳道；不在前端拼数组，不自动宣称绝对对齐。

用户问题
设备端、客户端/服务端或两次复现需要跨来源观察同一时间附近的证据。
核心价值
在不篡改来源的前提下共享调查游标，比较两个来源的邻近证据。
主要交互流程
创建两来源会话 → 为各 segment 选择锚点 → 确认 offset/置信度 → 双泳道并排、共享十字游标 → 每行显示来源、原始时间与偏移 → 回到原始来源。
功能边界
首版固定两个来源；无可靠锚点就不自动对齐；不拼接文本、不统一行号、不画因果连线；两个窗格独立查询。
依赖
引擎级 MultiSource Session、复合窗口读取、每来源 generation/内存预算、segment 时钟与 provenance。
风险
破坏单 Session 不变量、双 10GB 资源预算、时钟漂移、伪精确对齐和交互/查询语义复杂化。
优先级
P2/P3 边界探索。吸引力高但架构契合度最低，应在其他基础完成后最后推进。
验证方式
偏移、回拨、跨年和无锚点合成数据；两份 10GiB 窗口性能与内存回归；不得出现前端全文拼接；用户理解 offset 误差。

Evidence gates

验证与退出条件

功能做得出来不等于方向成立。验证必须覆盖任务效率、事实正确性、性能预算和信任边界。

用户任务

  • 5–8 名 Android/OEM QA 或工程师用最近一次已脱敏调查做回放。
  • P0：15 秒识别抓取状态、30 秒恢复配方；时间定位显著快于关键词路径。
  • 接收方能从证据包复现同一调查路径，并区分事实与用户备注。

事实正确性

  • 跨年、回拨、续行、PID 重用、多进程和来源失配使用 oracle。
  • Problems 缓存必须与全量重扫逐字段一致，任一身份失配即拒绝。
  • 近似摘要显示误差、样本和 exact/approx；时间邻近不画因果。

性能与有界性

  • 安全导出、摘要与缓存分别跑 10GiB 基准并记录私有内存。
  • 新视图继续只取可见窗口，不复制正文，不扩大 IPC 到无界集合。
  • 恶意 ZIP、结构化深度炸弹和跨块规则都有资源上限与取消。

信任与隐私

  • 安全导出断网运行、源哈希不变、规则报告零原文。
  • 原型与未来产品都不加载日志中的 URL、Markdown 或外部实体。
  • Unknown、有损 coverage、失效引用和“未检出不等于安全”持续可见。
明确不做：整份日志云端上传或默认 AI 根因、默认有损采集、远程生产日志平台/SDK、任意插件市场、完整 Android Studio DSL/SQL、前端多文件拼接；iOS、kernel `/proc/kmsg` 与移动端仍不在产品范围内。
